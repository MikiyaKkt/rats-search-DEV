# 多语言搜索阶段 1 验证报告

**结论**　随包 Manticore 的字符分词能支持中文、日文、韩文和泰文，同时保留现有英文标题前缀行为。实际匹配还需要两层校验。阶段 2 处理连续文字和短语的查询规则，阶段 3 验证同一文件路径是否满足所有条件。本期只在隔离索引中做验证。

## 环境与复跑

- 基线为 Rats Search v1.1.0（`3965c28`）。引擎为随包 Windows x64 Manticore 17.5.1（`d4cc0969e@26020616`）。测量在 Windows x64（`10.0.26320`）、AMD Ryzen 7 5700X 和 Node.js 24.22.1 上完成。
- 直接从应用配置提取 `torrents` 和 `files` 两张表。对照组保留原配置，试验组仅为两张表增加 `charset_table = non_cont`、`ngram_len = 1`、`ngram_chars = cont`。标题保留 `min_prefix_len = 3` 和 `expand_keywords = 1`。
- 两组加载相同的 10,022 条种子记录和 50,026 条路径，其中 22 条种子用于可断言的正反例，其余是固定生成的多语言数据。每条样本的 Info Hash、分类、大小、做种人数和路径可在探针输出中核对。

```powershell
node benchmarks/search/phase1-manticore.cjs
```

探针会在 `.tools/search-phase1-*/` 写入两套配置、引擎日志和 `result.json`。JSON 保留每个用例的预期、实际命中哈希、分词位置、完整高亮片段和分查询延迟。两套实例依次使用独立目录和回环端口，结束时只关闭探针启动的进程。 [复现脚本](../benchmarks/search/phase1-manticore.cjs) · [应用索引配置](../src/data/manticore.cpp#L762)

## 正确性结果

| 查询 | 现有配置 | 字符分词试验与校验 |
| --- | --- | --- |
| `电影` | 标题和路径均无结果。 | 用字符短语能找到 `经典电影合集`，排除 `电台摄影` 和 `影电`。引擎也会召回 `电-影`。探针加上对原文连续子串的校验后，标题和文件用例均得到预期集合。 |
| `音楽`、`영화`、`เพลง` | 标题和路径均无结果。 | 三种文字都能命中对应的标题和路径，排除 `音の楽`、`영과화`、`เพลกง`。 |
| `电影 1080p`、`1080p　电影` | 中文部分未分词，含 `1080p` 的无关记录也会命中。 | 两种顺序得到相同结果。标题候选准确，文件候选仍包含分别命中两个条件的跨路径记录。逐路径试验只为同时满足两项的路径返回高亮。 |
| `"星际 穿越"` | 中文样本无结果。 | 排除夹有 `经典` 的标题。文件表里的换行没有打断词项位置的相邻关系，因而也返回跨行候选。逐路径试验排除了隔词和跨行用例。 |
| `导演剪辑版` | 标题及路径均无结果。 | 标题可命中。另一个只有内部文件名包含该词的种子也能通过文件查询找到。标题还验证了只出现在 `info.name` 的关键词。 |
| `Ubuntu Linux`、`ubun`、`ubun*` | 标题能够进行多词和前缀查询。文件索引原来没有启用前缀。 | 两组的这三个用例返回相同集合。 |
| `"Ubuntu Linux"` | 应用会转义引号，按普通多词查询。 | 直接传给引擎的短语仍会匹配 `Ubuntux Linux`。查询加 `OPTION expand_keywords=0` 后只命中 `Ubuntu Linux`。同一查询为引号外的 `archiv` 显式加前缀分支后，短语仍然精确且能命中 `Archive`。 |
| `"ubun* linux"` | 沿用原通配符处理。 | 仅转义 `*` 并关闭自动扩展仍会匹配 `Ubuntu Linux`。先把引号内的星号按当前分词配置当作分隔符处理，再关闭自动扩展，排除了该前缀误命中。 |

## 性能基线

两组分别以 250 条种子为一批导入标题和路径。导入耗时包含批量 SQL 往返，索引体积在两张表刷入磁盘后统计。延迟包含本机 HTTP 往返与结果解析，使用相同 SQL 和固定工作负载。每张表四条查询，各预热 5 次并测量 40 次。当前样本只用于对照，尚未测量应用层的逐路径校验、迁移或生产库负载。

| 指标 | 原配置 | 字符分词 |
| --- | ---: | ---: |
| 批量导入耗时 | 533.4 ms | 532.0 ms |
| 标题索引体积 | 1,859,224 B | 1,984,061 B |
| 文件索引体积 | 1,945,464 B | 2,251,429 B |
| 标题延迟 p50 / p95 | 2.225 / 101.737 ms | 2.524 / 104.035 ms |
| 文件延迟 p50 / p95 | 1.775 / 2.706 ms | 1.804 / 3.248 ms |

在这组样本中，两张表合计增长约 11.3%。标题总体 p95 主要由覆盖大部分合成记录的 `catalog*` 主导，该单条查询的 p95 分别为 104.783 和 107.175 ms。文件组的 `科学資料 entry2` p95 从 2.679 ms 变为 4.316 ms。启用字符分词后，工作负载中含中文的查询会召回不同的记录，因此该对照衡量的是两种配置下的实际查询效果和开销。

## 后续阶段的实现依据

1. **阶段 2**　把连续文字先编译为字符短语，再用原始索引文本验证未加引号的连续词组。引号短语关闭自动前缀扩展，引号外普通英文仍要保留原前缀行为。探针验证了一个显式前缀分支组合，阶段 2 继续用英文回归集验证。 [Manticore 关键词扩展](https://manual.manticoresearch.com/Creating_a_table/NLP_and_tokenization/Wildcard_searching_settings)
2. **阶段 3**　以 `files.path` 的全文查询召回候选，再单独验证每条路径。探针中的逐路径 `CALL SNIPPETS` 能正确标注多词和短语样本，但仍会把 `电-影` 标为相邻字符。保持连续子串校验，并在全部条件通过后才输出高亮。逐路径方案的性能与分页行为留待阶段 3 测量。 [Manticore 高亮接口](https://manual.manticoresearch.com/Searching/Highlighting)

现有 `test_query` 和 `test_manticore_queries` 均已通过。阶段 1 已形成对照和实施依据，应用查询逻辑、正式索引配置和用户数据库未修改。
