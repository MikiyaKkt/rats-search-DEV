# S1 人工验证清单

包：`dist/RatsSearch-Windows-x64-s1.zip`。此包等待人工验证，尚未批准进入 S2。

建议解压到新目录，用独立数据目录启动，避免直接升级日常使用的数据：

```powershell
.\RatsSearch.exe --data-dir .\s1-validation-data
```

## 验证步骤

1. 打开 Settings → Downloads。设置下载/上传上限，例如 512/128 KiB/s；保存后无需重启。下载有稳定来源的大文件，观察上下行速率及文件真实增长。速率单位采用 1024，0 表示该层不限。
2. 同时添加至少 10 个有来源的任务。默认最多 3 个下载、2 个做种、2 个元数据任务和 1 个文件校验。元数据获取和校验不占下载槽；等待任务显示 Queued。
3. 将 Active downloads 从 3 降为 1，确认多余任务让位；再提高上限。手动暂停的任务不应被自动恢复。对等待任务点击 Queue first，检查其获得下一次下载机会；任务 Settings 中可修改队列优先级。
4. 打开任务 Settings。设该任务上限 64 KiB/s，再将全局上限设为 32 KiB/s，确认任务无法绕过全局限制。任务 -1 表示继承，0 表示取消任务自身上限；连接数 0 表示继承。
5. 检查完整下载后的上传速率；达到完成状态仍可查看任务设置。分别使用 TCP 来源与 uTP 来源（若可用），检查限速及热修改后传输仍继续。
6. 正常退出后使用同一数据目录重启，核对上限、任务覆盖、顺序和用户暂停意图。重新校验期间不要把历史 completed 当作数据已经有效。旧数组会话首次迁移后默认暂停，需手动恢复。
7. 使用包含中文、空格、括号的目录与文件名重复下载，验证无乱码目录，校验完成且文件可读取。S0 的 UTF-8 文件接口修复保留。
8. 在测试数据目录中使用不可写的会话保存位置，检查策略应用但保存失败的提示；不要在生产数据上进行破坏性测试。

## 当前行为边界

- 限速作用于共享 BT Client 的内容负载；协议/元数据使用独立的双向合计 64 KiB/s 控制预算。DHT、Rats P2P、数据库复制、TCP/UDP 报头和传输层重传不计入内容速率，不代表整个进程网卡带宽上限。
- 公平带宽采用活动任务等份预算；队列优先级只决定准入。空闲任务的份额暂不动态借给其他任务，因此有多个活动但无来源的任务时，总吞吐可能低于全局上限。
- 内容桶初始为空，公开容量 B = max(16 KiB, min(R/10, 1 MiB))。应用层请求预约上限为全局 32 MiB、单任务 512 KiB；低速及热降限应按字节界限理解在途数据和缓冲，而不是要求所有短窗口瞬间平滑。
- 上传统计位于 PeerLink 实际接受字节的边界：TCP 内核发送缓冲/uTP 有界发送队列；不把尚未交给传输层的整块数据提前算成上传完成。
- 等待老化每分钟提高一级准入分数；有其他任务等待且当前任务连续 120 秒无校验进度时，让位并冷却 60 秒。非常低的限速会影响校验进度的更新频率。
- **S1 不提供真实文件选择与可调分块。** 旧文件勾选仅保留兼容状态；这两项属于后续阶段，不能依据勾选判断磁盘只写入所选文件。

记录问题时请包含包内 build-info、设置数值、任务状态、复现步骤及日志；涉及路径时保留原始 Unicode 名称。
