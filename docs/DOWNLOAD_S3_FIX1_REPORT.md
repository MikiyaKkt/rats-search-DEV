# S3 fix1：下载设置与进度修复

## 修复结果

1. **启动恢复不再逐任务弹出设置窗口。** 恢复任务保留文件优先级、确认状态、暂停意图及任务策略。引擎尚未加载元数据或磁盘清单时，不用初始默认值覆盖会话设置；原生恢复记录落后时，在开放内容下载前重放已保存的选择。原生清单修订号更高时采用较新的选择；历史文件列表与元数据不匹配时暂停任务，等待人工处理。新建任务仍保留首次文件确认流程。“保存”会一起提交窗口中的文件选择及任务策略。
2. **启动即显示已保存进度。** 会话读写补齐任务和文件的已校验字节、所选总量及所选已校验字节。等待启动、等待元数据或校验期间保留历史进度，通过 `progressPending` 标记其尚待验证；完成事件、删除完成任务等动作仍以引擎实际校验结果为准。进度变更每 10 秒保存一次，完成时立即保存；正常退出仍保存。
3. **修改选择不再清空全部分片并重扫磁盘。** 独占磁盘队列屏障完成后，保留存储仍有效的已校验分片，丢弃未验证的在途块状态，按文件选择重新汇总进度。仅失去边界存储的分片作失效处理。边界清理从逐个探测整个种子的潜在片段文件，改为枚举实际存在的引擎片段；新勾选但尚无数据的非空文件由首次写入创建。服务在应用完成后立即推送文件与进度，无须等待下一秒轮询。
4. **下载设置本地化。** 修复任务窗口缺少 `Q_OBJECT` 导致翻译上下文不匹配的问题；补齐简体中文、日文、德文、法文、西班牙文、俄文、韩文的任务设置、全局下载选项、做种条件、带宽计划及分片图说明。打开的下载设置窗口响应语言切换，同时保留输入值和文件选择。

## 响应时间验证

- 128 GiB 逻辑种子、32,768 个分片、两个文件，连续切换文件选择 10 次，专项实测最慢 **8 ms**。该用例使用受信任的恢复位图，不分配 128 GiB 文件，验证选择变更不触发磁盘重扫、已校验进度不丢失。
- 实际本地网络下载用例验证：增加一个未下载文件后，进度立即按已校验字节由 100% 变为 50%，原有已校验字节保持不变；取消新增选择后恢复 100%。用例要求选择操作小于 500 ms，并继续验证部分做种上传和删除文件后的显式重校验。
- 服务用例要求选择完成事件及进度推送在 500 ms 内到达，不等待 1 秒状态轮询。
- 500 ms 检查针对已初始化任务的选择变更与进度汇总；首次磁盘完整校验、显式重新校验及实际边界数据迁移仍受磁盘和数据量影响。它们不会再成为每次选择变更的默认全量重扫步骤。

## 人工复验

1. 设置若干任务的限速、策略、文件优先级和不同选择，直接点“保存”；暂停其中一个，退出并重新启动。确认无逐任务弹窗，任务设置和暂停意图保持。
2. 观察启动列表：已有进度立即显示；暂停任务也有历史进度。恢复后实际校验如发现文件缺失，应按真实状态修正进度，不提前通知完成。
3. 在正在下载的多文件任务中新增/取消文件选择，确认原有已校验数据不先归零，显示及时更新。显式“重新校验”仍能检测缺失或损坏的数据。
4. 切换界面语言，重新打开或观察已经打开的下载设置窗口，确认选项、做种条件和带宽计划均随语言变化，正在编辑的数值、文件名和勾选状态保持。
