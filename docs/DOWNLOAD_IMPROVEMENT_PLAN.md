# 下载功能优化方案（待人工审查）

日期：2026-11-15。状态：设计草案，尚未批准实施。

本阶段仅提交方案，不修改下载行为、不升级依赖、不重新发布程序。本文中的接口、默认值、性能阈值均为建议，需审查后确认。

## 1. 目标与范围

让用户可靠控制下载带宽、同时运行的任务、种子内部的文件，以及下载顺序；保留桌面和无界面服务共用一套行为。优先解决“设置实际生效”和“进度能够说明落盘情况”，再提供高级调优。

参考对象按 BitComet 理解（用户原文 BitComent）。借鉴其全局/任务两级设置、文件树和任务属性交互；不要求复制全部功能或专有协议。

首轮范围：上下行限速、任务队列、真实选择性下载、文件优先级、可靠状态与续传。后续范围：顺序下载、分片视图、调速计划、缓存与做种策略。暂不纳入 HTTP/FTP/eMule、多镜像、BitComet 长效种子协议、自动关机和内置播放器。

## 4. 设置模型与建议默认值

UI 使用 KiB/s、MiB/s；内部/API 使用整数 B/s，避免单位歧义。上限字段中 0 表示不限；任务字段 null 表示继承。负数、溢出和未知枚举拒绝，不静默纠正。

| 设置 | 层级 | 建议初始值 | 说明 |
|---|---|---|---|
| 最大下载/上传速度 | 全局 | 0 / 0 | 保持现有不限速体验；不通过固定上传比例猜测用户带宽 |
| 最大下载/上传速度 | 单任务 | null / null | 0 仅取消任务自身上限，不能绕过全局上限 |
| 同时下载任务数 | 全局 | 3 | 仅内容下载占用下载槽 |
| 同时做种任务数 | 全局 | 2 | 达到所选目标的部分任务也占做种槽，但不能宣称完整 seed |
| 同时获取元数据任务数 | 全局 | 2 | 另计槽位；等待用户选文件时不占下载槽 |
| BT Peer 总连接/单任务上限 | 全局/任务 | 200 / 50 | 双重约束；实际硬上限、线程开销需 S0 压测确认 |
| 队列顺序 | 全局/任务 | FIFO + 手动优先级 | 支持上移、下移、置顶；不设置绕过全局约束的“强制启动” |
| 新任务文件选择 | 全局 | 下载前确认 | 磁力先取元数据，再显示确认框；无界面 API 必须显式选择策略 |
| 文件优先级 | 单文件 | normal | 第一版 skip/normal/high；低优先级留到需要时扩展 picker |
| 分片策略 | 单任务 | rarestFirst | sequential 为高级选项 |
| Peer 请求窗口 | 高级 | auto | 首轮不改变现有窗口；S3 加入有界自动调整与手动配置 |
| 磁盘缓存/预分配 | 高级 | 保持现有 | 根据实测决定内存预算；不默认预分配所有未选择文件 |
| 做种停止条件 | 全局默认+任务覆盖 | 不限 | 后续支持分享率、时长、达到任一/全部条件；不自动删除文件 |

速率限制约束的是 BT 内容负载，不承诺限制整个进程或网卡流量。DHT、Tracker、Rats 搜索、投票等控制流量另设小额预算并在说明中列出。复用同一 BT 引擎的后台内容传输必须纳入全局内容预算，不能成为限速旁路。

## 5. 用户交互

### 5.1 新建下载

输入磁力或导入种子 → 获取元数据 → 展示保存位置、可用空间、文件树与所选大小 → 配置任务上限/优先级 → “加入队列”或“开始”。

磁力等待元数据期间显示独立状态、超时原因及重试按钮。默认未确认文件前不开始内容下载；从搜索结果得到的文件列表只作展示预览，以验证后的种子元数据为准。

文件树支持目录三态勾选、全选/全不选、按扩展名选择、大小排序、搜索名称；界面排序不能改变引擎 fileIndex。全不选时禁止开始，不触发“瞬间完成”。显示“所选大小 / 整个种子大小”，并提示跨文件分片可能引入少量额外数据。

### 5.2 设置与任务列表

- 全局设置增加“下载”页：带宽、下载/做种/元数据槽位、默认目录和行为；高级参数折叠。
- 底部状态栏显示总下载/上传速率和当前全局限额，点击可调整或使用预设。
- 下载列表增加状态、已校验完成/所选大小、上下行速率、ETA、队列位置、有效限额；不将“累计接收量”作为文件进度分子。
- 任务属性包含“常规 / 文件 / 连接与分片 / 统计与错误”；右键提供暂停、恢复、排队、优先级、重新校验、打开目录。
- 文件页显示所选/优先级、大小、已校验字节与进度。分片页使用按区间聚合的位图，避免大种子创建海量 UI 控件。
- 正在运行时修改选择显示“正在应用”，收到引擎确认后才更新为生效；不能只更新复选框后宣称成功。

## 6. 核心设计

### 6.1 限速

新增全局/任务双层令牌桶和公平带宽分配。由 reactor 使用单调时钟驱动，不能在 GUI 线程或网络回调中 sleep。上传令牌在内容实际发送处扣减；下载在请求发出前预留预算，取消、超时、短响应需释放预留，并结合接收背压限制突发。TCP 与 uTP 共用预算，不能只覆盖一种传输。

任务上限是独立约束：所有任务合计受全局上限限制，每个任务还受自身上限限制。采用可测试的公平轮询/加权分配，低优先级保留最低服务机会，不允许高优先级无限饿死其他任务。

降低限额时已发出的请求和在途响应不能撤回全部；界面显示短暂收敛。动态约束总请求窗口，避免低限速下仍向数百个 Peer 发出大批请求。End-game 重复请求同样消耗预算。

### 6.2 队列与状态

新增 DownloadScheduler。区分用户意图（运行/暂停）、运行阶段（取元数据/校验/下载/所选完成/完整完成）及调度原因（排队/无选择/磁盘错误/等待网络），不要用一个 paused 布尔值承担全部语义。UI 可派生为：获取元数据、等待选择、排队、校验中、下载中、用户暂停、所选完成、做种、已停止、错误。

槽位分配建议规则：

1. 用户暂停和致命错误立即释放内容下载槽；正常校验独立限并发，避免磁盘争用。
2. 任务启动必须“创建为非活动 → 应用选择和策略 → 调度启动”，杜绝添加后先偷偷下载。
3. 修改最大并行数为更低值时，将队尾任务安全退回队列，保留数据；不修改用户暂停意图。
4. 恢复任务回到调度器，不直接绕过槽位启动；完成后根据做种槽位决定排队或上传。
5. 无 Peer/无速度先标记 stalled；建议可配置 120 秒观察后释放槽、60 秒冷却，重试次数和等待时长均可见。该参数需压测，队列轮转不视为失败。
6. 下载队列优先级与带宽优先级分别建模；元数据任务有超时、取消和独立预算。

### 6.3 真正的选择性下载

按元数据中的文件字节区间计算所需 pieces：文件非空区间 [offset, offset+size) 映射到覆盖该区间的分片集合；分片优先级取其覆盖的已选文件的最高优先级。空文件单独处理，不生成非法 piece 下标。

跨文件边界的 piece 必须完整下载并按原始 piece hash 校验。建议将未选文件对应的边界字节保存在任务专属 `.parts/<infohash>/` 边界存储中，避免创建用户未选择的最终文件；统一读写映射使校验、上传、恢复都能访问同一份完整分片数据。所选文件字节写入其正常路径。边界存储必须有稳定地址、空间统计和清理规则，不能在暂停或重新勾选后丢失。

运行时取消选择：停止发出新请求，取消可取消的请求；已到达/正在写入的数据安全处理，不默认删除已有文件。重新勾选复用已校验数据，必要时重检；切换选择不得截断已有文件。

明确三种量与两种完成状态：

- totalBytes：整个种子大小；wantedBytes：当前所选文件大小。
- wantedVerifiedBytes：已通过完整分片校验的数据与所选文件区间的交集大小，按文件去重求和。
- selectedComplete：wantedBytes > 0 且所选数据校验完成；fullTorrentComplete：全部种子分片齐全。
- 任务进度 = wantedVerifiedBytes / wantedBytes；全不选为等待选择，不能除零或进入完成事件。
- 仅 selectedComplete 时可上传已有的完整校验分片，但不得发送完整种子完成通告；Tracker left 按整个种子的缺失数据计算。现有 picker 的 is_finished 不能直接决定完整 seed 状态。

提供 selectedCompleted 独立事件，旧 completed/downloadCompleted 暂保留“整个种子完整完成”的语义；GUI 使用新状态显示“所选文件完成”。removeOnDone 旧行为继续仅作用于完整完成；新增 stopWhenSelectedComplete 控制选择性任务自动停止，避免兼容性歧义。

### 6.4 “分块”功能边界

BT 种子的 piece 长度和哈希由元数据决定，不能像 HTTP 下载一样任意改成 8/16 段。协议 block 大小首轮保持原值。

可提供的控制是：分片策略、Peer 数、每 Peer 请求窗口、全局在途字节、磁盘缓存和背压。优先开放策略，其他高级参数在 S3 经基准验证后开放。顺序模式仅调整已选文件的 piece 获取顺序，仍须按完整 piece 校验，不修改 info hash。文件首尾优先也只作用于已选文件，且不保证所有媒体可预览。

### 6.5 错误、进度和持久化

引擎快照增加 receivedPayloadBytes、uploadedPayloadBytes、verifiedBytes、wantedVerifiedBytes、uploadRate、fileVerifiedBytes、stateReason、lastError 等。保留旧字段的既有含义并标记 deprecated，新增 UI 使用明确字段，不悄悄改变 API 旧分子语义。ETA 由剩余所选有效字节和滑动平均有效速率估算，校验/排队/无速度显示“—”。

将磁盘满、权限不足、非法名称等持久错误传给服务并停止内容请求；短暂 I/O 错误有限次退避后转为需人工重试。哈希失败按数据/Peer 问题记录，不能统称磁盘错误。错误不推进有效进度；无 Peer 不等同致命失败。

会话升级 schemaVersion，增加稳定 fileIndex、任务策略、排队顺序、用户暂停意图、选择确认状态和修订号。使用 QSaveFile 原子保存，新增字段向后兼容；旧会话缺少可靠策略时默认暂停待确认，不自动恢复全部文件下载。旧 completed 标记恢复后需与引擎校验状态核对，不能永久覆盖真实数据缺失。

恢复顺序：加载策略 → 建立暂停任务 → 校验元数据及缓存 → 恢复选择/优先级 → 对齐 resume 数据 → 调度器分配槽位。策略文件损坏时保留已有内容，展示恢复错误，不退回静默全选。

| 新 DownloadScheduler / DownloadPolicy | 槽位与公平性；纯策略便于使用假时钟测试 |
| [ConfigStore](../src/app/config_store.h) / [TorrentSessionStore](../src/services/torrent_session_store.cpp) | 全局配置、任务覆盖、schema 迁移与原子持久化 |
| [Application](../src/app/application.cpp) | 组装、启动与配置热更新，保留统一生命周期 |
| [API Router](../src/rest/api_router.cpp) | 复用现有命令分发体系，增量扩展下载命令 |
| [下载列表](../src/ui/downloadswidget.cpp)、[文件树](../src/ui/torrentfileswidget.cpp)、[设置](../src/ui/settingsdialog.cpp) | 对应状态、真实选择、限速与队列交互 |

拟增服务方法：setGlobalPolicy、setTaskPolicy、setFilePriorities、moveQueueItem、recheck、retry。返回值区分校验失败、引擎拒绝、任务不存在与持久化失败；不再全部压成 bool。调用引擎时不得持有服务 mutex 等待 reactor，避免死锁。

沿用现有 HTTP/WebSocket 命令路由，暂不臆造新的 URL 格式：

| 命令 | 输入/输出重点 |
|---|---|
| download.policy.get/set | 全局策略、revision、effectivePolicy |
| download.taskPolicy.set | hash、expectedRevision、任务覆盖、返回应用结果 |
| download.files.set | hash、expectedRevision、[{index, priority}]；一次全量验证后原子生效 |
| download.queue.move | hash、beforeHash；更新后返回顺序和 revision |
| download.recheck / download.retry | 明确状态限制，返回操作标识与最终事件 |
| download.list / progress 事件 | 增量扩展有效字节、上下行、所选完成、错误、队列原因 |

示例（设计草案）：

```json
{
  "hash": "<40-hex-infohash>",
  "expectedRevision": 7,
  "policy": {"downloadLimitBps": 2097152, "uploadLimitBps": null, "queuePriority": "high"}
}
```

API 返回成功须表示引擎已接受并应用；异步操作返回 accepted + operationId，由事件明确最终结果。服务策略若已应用但持久化失败，返回可辨识的 appliedNotPersisted，不能假装全部成功。文件索引越界、重复索引、元数据未知、修订冲突一次性拒绝；旧 selectFiles 映射到 skip/normal，保留旧客户端兼容。

| S0 可靠性与接口验证 | 有效字节/错误模型；非活动创建；验证共享引擎边界；测试夹具和基准 | 不再将接收量显示为落盘进度，持久 I/O 错误停止重取 | 3–5 人日 |

| S2 真实文件选择 | 元数据确认流程、skip/normal/high、边界存储、部分完成/恢复 | 未选文件不生成最终文件，所选内容逐字节正确，旧客户端兼容 | 10–15 人日 |
| S3 高级体验 | 顺序/首尾优先、分片视图、有界请求窗口、缓存、调速计划、做种条件 | 性能/内存/磁盘不回退，有独立配置迁移与测试 | 7–12 人日 |

估计为单人有效工程时间，包含开发与测试，合计约 27–44 人日；不含人工审查等待和不可预见的上游引擎重构。S0 后重新估算。首个用户可用版本建议到 S2，S1 可单独验收。优先级顺序可在审查时调整，但不建议跳过 S0。

## 9. 验收与测试设计

统一使用本地可控 seed/Peer 和确定性数据，不依赖公网种子的瞬时速度。测试覆盖 TCP/uTP、单/多文件、多任务和重启；沿用 Windows x64 一键构建，全平台 CI 按支持范围补齐。

| 场景 | 验收标准 |
|---|---|
| 全局/任务限速 | 对可饱和数据源，使用假时钟验证任意窗口内容字节 ≤ R×T+B+I；B 为公开的桶容量、I 为有界在途量。真实传输预热后观测 60 秒，平均超限 ≤5%；低速场景按上述字节界限验收，不用任意宽松百分比掩盖突发 |
| 热更新限额 | 不断开全部任务；新请求预算 1 秒内更新，在途响应在声明的预算内收敛；0/继承组合不绕过全局限制 |
| 并行数 | 添加 10 个任务，上限 3 时活动内容下载始终 ≤3；调低、暂停、错误、完成后槽位正确释放，元数据槽位独立 |
| 公平性 | 多个持续可下载任务获得服务机会；高优先级不能让其他任务无限等待；具体权重与最大等待目标在 S0 确认 |
| 文件选择 | 三文件种子只选中间文件：最终目录无未选文件；中间文件与源逐字节一致；额外边界数据仅来自所需 piece 覆盖区间并单独计量 |
| 边界与运行时变更 | 跨文件 piece、零字节文件、全部取消、勾回、并发排序、多次调整均正确；正常数据不被截断或删除 |
| 部分完成 | 所选进度到 100% 只触发所选完成；缺少其他 pieces 时不发布完整完成通告，Tracker left/Peer bitfield 与实际一致 |
| 重启续传 | 保留限速、选择、优先级、队列位置和用户暂停；不短暂全量启动；边界数据重检成功；旧会话/损坏会话行为明确 |
| 磁盘错误 | 磁盘满、只读、路径无效不无限重取；错误可见；重试后基于实际校验结果继续 |
| 编码 | 中文、日文、emoji、组合字符与 Windows 保留名测试；非法名称给出可操作错误，保持原始元数据哈希不变 |
| 性能 | 以当前基线比较吞吐、CPU、内存和写入放大；不限速吞吐下降目标 ≤5%，失败时回到 S0 分析，不直接扩大资源上限 |
| UI/API | 设置有效值一致；无效请求原子拒绝；并发修改可检测修订冲突；旧命令仍可工作 |

每阶段交付：变更说明、测试记录、Windows 免安装包，以及已知限制。依赖修改通过可追踪的 librats revision 或仓库补丁保存，继续验证补丁可应用于锁定版本。
