# 多语言与高级搜索执行计划

以 v1.1.0（`3965c28`）为基线。先让本地索引里的新旧种子都能按多语言关键词、短语和多个条件检索，再交付可选的错字容忍和跨节点搜索。标题与文件路径两条查询路径都纳入验证。普通搜索继续使用现有筛选和排序，Info Hash 精确查询、磁力链接和 DHT 回退沿用现有流程。

## 查询约定

| 输入 | 预期行为 |
| --- | --- |
| `电影` | 匹配标题或路径中的连续子串，如 `经典电影合集`。排除 `电台摄影`。 |
| `电影 1080p` | 空格或全角空格分隔条件，所有条件都必须出现，顺序不限。 |
| `"星际 穿越"`、`“星际 穿越”` | 按分词后的顺序和相邻位置匹配短语。允许短语前后有其他内容，排除 `星际 经典 穿越`。 |
| `"导演剪辑版" 1080p` | 同时满足短语和普通词条件。 |
| `ubun*` | 保留现有显式通配符行为。引号内的星号不展开。 |
| `ubntu`、`星际穿悦`（开启模糊查找） | 可补充 `ubuntu`、`星际穿越`。普通命中在前，模糊命中在后。 |

引号短语使用索引的大小写、标点和空白规则。文件搜索的所有条件必须落在同一条文件路径上，命中路径原样显示并标注高亮。名称或路径的普通搜索保持现有类型、安全搜索、大小、文件数和排序规则。40 位十六进制 Info Hash 继续走精确查询。未闭合引号给出可纠正的提示。

## 阶段 1 · 验证随包 Manticore

**目标**　用真实全文索引证明连续文字、短语和英文前缀可以共存，为后续的查询实现与重建提供可复现的样本和性能对照。

**执行**

1. 使用独立数据目录与端口启动随包 `searchd`。复制 [索引定义](../src/data/manticore.cpp#L762)，用同一批数据分别建立现有配置与试验配置。试验给 `torrents` 和 `files` 加入 `charset_table = non_cont`、`ngram_len = 1`、`ngram_chars = cont`，保留现有标题前缀配置。
2. 固定样本的哈希、标题、文件路径、分类、大小和做种人数，逐条记录应命中与应排除的哈希。样本覆盖中文、日文、韩文、泰文、英文和中英混排，也覆盖文字连续、逆序、相隔一字、连字符、路径分隔符与跨路径凑词。
3. 分别验证标题和路径的单词、连续词组、带引号短语、混合条件和英文前缀。记录分词位置与高亮输出，尤其检查 `files.path` 中的换行是否允许短语跨路径命中、短语里的 `*` 是否触发展开，以及默认的前缀扩展是否影响精确短语。
4. 记录引擎版本、配置、样本规模、索引体积、建库耗时和查询延迟。用同一机器、数据和查询集记录预热后的 p50、p95，后续各阶段复用这组基线。

**验收**　`电影` 命中连续样本，错序和隔字样本被排除。英文用例和原有通配符行为通过。四类连续文字各有正反例。标题和路径都形成可复现的验证记录。若随包引擎在短语或高亮上有差异，先确定阶段 2、3 的补充校验方式，再接入应用。

**验证结果**　阶段 1 已完成。字符分词验证通过。阶段 2 须处理分隔符与短语的前缀扩展，阶段 3 须验证同一路径及其高亮。实测结果、性能对照和复跑命令见 [阶段 1 验证报告](SEARCH_PHASE1_REPORT.md)。

## 阶段 2 · 统一查询解析和入口校验

**目标**　一次定义用户输入的语义，让标题、文件路径、桌面和 REST 对同一查询使用相同规则。

**执行**

1. 在 [SearchService](../src/services/search_service.h) 与 [查询构造](../src/data/query.cpp) 的现有职责内拆开解析与 SQL 构造。解析阶段识别普通词、连续文字词组、直引号与中文引号短语、带显式通配符的词。空格、制表符和全角空格可分隔引号外的条件。同一查询中的所有条件采用 AND。
2. 由查询构造层转义每个条件的文本，然后生成对应的全文表达式。连续文字按相邻位置匹配，精确短语抑制通配符展开，普通英文保留现有前缀行为。标题和文件查询共用解析结果。根据阶段 1 的实测结果处理引擎差异。
3. 从桌面 [搜索入口](../src/ui/mainwindow.cpp#L1011) 与 [API 路由](../src/rest/api_router.cpp#L345) 接入统一校验。未闭合引号和空短语返回可纠正的提示，避免把语法错误显示成零结果。放行原先被长度限制拦截的两字连续文字查询，保留各入口现有的英文短词行为。
4. 把 Info Hash 和磁力识别与全文解析分别验证。检查纯哈希精确定位、磁力链接未命中后的回退，以及引号内的普通文本行为。由 [查询单元测试](../tests/test_query.cpp) 覆盖解析，真实匹配进入 [Manticore 集成测试](../tests/test_manticore_queries.cpp)。

**验收**　`电影 1080p` 与 `1080p　电影` 的命中集合一致。引号内词序变化或插入其他词会改变结果。未闭合引号在桌面和 API 都有提示。英文前缀、`*`、哈希、磁力和已有筛选排序用例通过。

**验证结果**　阶段 2 已接入共享解析，并在随包 Manticore 的新索引上验证两字连续文字、精确短语、多词 AND、英文前缀和本地哈希及磁力查询。标题的连续字串校验在分页前执行，文件端暂按索引记录召回并校验高亮片段。Windows Release 构建和 31 项 CTest 全部通过。REST 冒烟测试使用隔离数据目录和合成种子，两个查询端点返回一致的引号错误提示。历史索引重建和完整的逐路径校验与分页将在阶段 3 实施。高级语法暂由本地索引处理，节点协议支持在阶段 5 接入。

## 阶段 3 · 文件路径校验与已有索引迁移

**目标**　让新写入、导入和旧库里的种子遵循同一匹配规则。文件搜索只返回真实命中的路径，并以筛选后的种子为单位分页。

**执行**

1. 在 [文件查询](../src/data/torrent_repository.cpp#L520) 中用全文索引召回候选，再以单条路径为单位验证全部条件。高亮与查询共享匹配语义。只返回通过校验的路径，显示保留原路径文本。
2. 应用所属种子的类型、安全搜索、大小和文件数筛选，按哈希去重并遵循请求排序。排序值相同时用稳定键打破并列。在结果层应用 `offset` 和 `limit`。用多批候选验证分页能跨过被筛掉的行，测量深分页代价并验证索引查询窗口边界。
3. 在 [现有迁移机制](../src/services/migration_service.cpp#L303) 中添加独立的分词升级记录。先确认两张表已加载新配置，再按稳定行 ID 分批读取并重写。复用仓库现有的行编码和批量写入能力，保留 ID、哈希、名称、原始路径与文件大小、分类和统计字段。
4. 为两张表分别保存最近一次确认写入的游标及完成状态。中断后重新执行未确认批次。根据阶段 1 的规模测量确定迁移批次和用户可见进度。若采用后台迁移，明确写入协调与索引状态提示，避免旧批次覆盖新更新或删除的记录。两张表都完成前持续显示迁移状态。
5. 使用旧配置建库后原地升级，覆盖跨批次、单表完成后退出、批次写入失败后重试、已有空文件列表以及升级后继续索引新记录。

**验收**　只有 `电影.mkv` 与 `1080p.txt` 两条独立路径的种子，在文件查询 `电影 1080p` 时被排除。筛选丢弃前一批候选后，后续合法命中仍能进入对应页。相邻页没有重复且合并结果与未分页对照一致。迁移可续跑，完成后运行前后数据完整性检查，旧种子和新种子都能按新规则检索。

**验证结果**　阶段 3 已接入逐路径匹配与高亮，排序和分页在父种子筛选之后执行。同一哈希只返回一次，同值以行 ID 确定顺序。文件候选按行 ID 分批读取，可越过 Manticore 的默认查询窗口。显式排序仍要走完匹配候选，内存只保留偏移量加页大小的最优结果。

旧索引在应用启动时重建。每张表以 500 行为一批，在确认写入并落盘后原子保存游标。迁移测试覆盖两张表的续跑、写入已应用但确认丢失，以及重启后的重复执行保护。迁移前后逐列对比标题和文件记录，附带的统计和元数据保持一致。另用实际 v1.1.0 的 Windows Release 程序生成旧库，再用本阶段构建确认两个 REST 搜索端点可命中旧种子，导入新种子后也能查到。

Windows Release 构建及 31 项 CTest 全部通过。隔离集成测试的单次样本中，1,134 条文件候选下，过滤后按做种人数取首页用时 30 ms，未过滤查询偏移 1,025 的深页用时 277 ms。重建 507 条标题和 506 条文件记录的续跑场景用时约 1.34 秒，包含注入中断、确认丢失和一次 Manticore 重启。生产大库耗时仍需在发布验收阶段测量。 [集成测试](../tests/test_manticore_queries.cpp#L604)

## 阶段 4 · 可选模糊查找

**目标**　在用户主动开启时补回轻微拼写错误造成的漏查，同时限制误报、查询耗时和扫描范围。

**执行**

1. 在桌面增加「模糊查找」开关，REST 增加可选布尔参数 `fuzzy`，默认关闭。首版仅放宽至少四个 Unicode 码点的普通词，每次查询最多有一个词允许一次插入、删除或替换。其余条件必须正常命中。保留引号、通配符和 Info Hash 的原有规则。
2. 先完成正常查询，再对每个符合条件的词分别试验有限的候选召回。连续文字可用分段锚点召回。英文等按词索引的脚本要单独验证词典或辅助索引能否覆盖词头拼错等情况。用编辑距离校验候选词，文件路径仍按单条路径验证。当前 Windows 随包未提供 Buddy，首选由应用控制召回和校验。
3. 分别测量候选上限、扫描行数、查询耗时和召回率。结合阶段 1 的基线确定工作量与耗时预算。达到预算时保留已确认的正常结果，并使模糊补充停止。记录为何停止，供测试和调试核对。
4. 正常命中优先，同一哈希有两种匹配时保留正常命中。各组内沿用请求排序和筛选，合并后再分页。桌面显示模糊命中标记，并验证表格排序、重复哈希与翻页时结果顺序一致。

**验收**　样本分别覆盖 `ubntu`、`星际穿悦`、词头错误、插入与替换。两字词、引号短语和通配符不被放宽。短语与一个错词可以组合，两处错误不会被同时修正。关闭模糊时的结果与阶段 3 一致。超出预算时普通结果可用，性能记录包含候选上限、p95 延迟和未召回样本。

**验证结果**　桌面新增默认关闭的「模糊查找」，两个 REST 搜索端点支持 `fuzzy=true`，只有补充结果带 `"fuzzy": true`。普通结果先于模糊结果，两组内按请求排序，按哈希去重后统一分页。合并标题与文件命中时，同哈希的普通命中优先。表头升降序都保持普通结果在前。

英文按单次编辑枚举词形，使用 Manticore 的字典精确查找决定哪些词形存在。中日韩泰文用原词的两段召回候选，再用原文校验一次编辑距离。文件候选在同一条路径上完成校验。当前使用现有索引。模糊补充暂在本地执行，节点协议在阶段 5 接入。 [Manticore 词典查询](https://manual.manticoresearch.com/Searching/Autocomplete#call-keywords)

首版每次最多尝试放宽前 4 个符合条件的词，每个词最多使用 16 个英文词形、校验 64 条候选记录，累计最多校验 262,144 个 UTF-16 码元。模糊补充使用 150 ms 软时限和每条候选 SELECT 最多 40 ms 的查询预算。达到时间预算时保留普通结果，丢弃这次模糊补充。较长输入、其他按词索引的文字和词形或候选超过上限的情况可能只返回普通结果。

Windows Release 构建及 32 项 CTest 全部通过，两个 REST 端点通过隔离实例冒烟验证。在预热后的 25 次隔离样本测量中，标题和文件查询的 p95 分别约为 3.38 ms 和 5.47 ms。正例 `ubntu`、`xbuntu`、`uubuntu`、`星际穿悦` 均召回预期种子。90 条合法模糊候选的预算样本返回 64 条，另外 26 条因上限省略，普通命中仍排在前面。注入字典查询超时后只返回普通命中。 [集成测试](../tests/test_manticore_queries.cpp)

## 阶段 5 · Rats 节点互通与发布验收

**目标**　让升级后的节点使用一致的高级检索规则，避免迟到结果串入下一次搜索，并验证旧节点兼容与发布包行为。

**执行**

1. 在 [节点能力握手](../src/services/peer_registry.cpp#L52) 和 [PeerApi](../src/peer/peer_api.cpp#L121) 接入查询能力标记。每次桌面搜索生成独立查询 ID，发送给支持新协议的节点。请求传递原查询和允许的匹配选项，结果按原 ID 回传。更换关键词、筛选或排序均产生新 ID。
2. 桌面只把 ID 匹配的新版响应合并进当前结果。旧节点继续收发兼容的普通查询。高级语法只发给已声明支持的节点。现有旧协议无法可靠关联迟到回复，验收记录需单列该限制。
3. 搭建两个隔离数据目录的节点，测试新对新、新对旧，以及回复乱序、重复和断线。核对短词规则、短语、多词、模糊开关、筛选和路径高亮。检查本地或远程的普通命中能覆盖同哈希的模糊命中，匹配路径合并不会重复。
4. 更新 [使用手册](MANUAL.md) 和 [API 文档](API.md)。运行查询单元测试、真实 Manticore 集成测试、节点互通测试和全量 CTest。用验证包分别复验新库、从 v1.1.0 升级的旧库、本地 API 和远程结果。复查 v1.1.0 发布时 Windows MSVC 在 `crawler_live_probe` 遇到的 Winsock 头文件冲突，确认自动发布使用的各平台构建通过。汇总查询延迟、索引大小、历史数据迁移耗时与已知兼容限制。

**验收**　新节点之间的两字查询、精确短语、同路径多词、模糊开关和筛选有效。上一轮的新版响应无法进入当前结果。旧节点的普通查询可用。包内程序通过新装及升级冒烟测试，交付可核对的测试结果和性能对照。

**验证结果**

- 两个隔离节点通过回环连接验证了两字中文、精确短语、同路径多词、模糊查找、筛选和路径高亮。用同一关键词变更排序后，上一轮的新版回复被丢弃。重复回复按哈希合并，普通命中优先于同哈希的模糊命中。节点断开后会移除其应答资格。 [双节点测试](../tests/test_peer_search.cpp)
- 正式 v1.1.0 包能向新版客户端返回兼容英文查询的标题和文件结果。旧节点只处理兼容的普通查询。旧回复缺少查询 ID，也可能缺少查询文本，因此连续提交兼容查询时，无法可靠识别后一轮已发出后才到达的旧回复。
- Windows x64 MinGW 的 33 项 CTest 全部通过，耗时 127.28 秒。`RatsSearch-Windows-x64-search-validation.zip` 的 SHA-256 核对通过。解压后的程序在新数据目录中通过 REST 导入和节点搜索验收，返回两字中文、带查询 ID 的文件路径和模糊命中。将同一个 v1.1.0 数据目录交给验证包后，旧条目完成重建，标题和路径可按多词检索，哈希与详情一致。新增种子在重启后仍可检索。包内程序也通过了中文路径下载冒烟测试。
- 本地验证包由含阶段 1–5 改动的工作区构建，源码与验证提交 `0521a81` 一致。包内 `build-info.json` 按打包脚本惯例记录工作区的基线 `3965c28` 和 `sourceModified: true`。ZIP 的 SHA-256 为 `753247abf1ee7ebede3a0d730455b41040e97e4ddd8a0bb8dfbf5cd469e18956`。
- 验证分支的 `0521a81` 通过 Windows x64（MSVC）、Linux x64 和 macOS ARM 的构建、测试及打包。Windows 的 `crawler_live_probe` 编译通过。该次运行跳过了 macOS Intel 和正式发布作业，v1.1.0 标签仍指向 `3965c28`。 [GitHub Actions](https://github.com/MikiyaKkt/rats-search-DEV/actions/runs/45006154786)
- 10,022 条合成种子的引擎基线中，两张索引合计增大约 11.3%，标题 p95 从 101.74 ms 变为 104.04 ms，文件 p95 从 2.71 ms 变为 3.25 ms。隔离样本的模糊标题、文件 p95 分别为 3.38 ms 和 5.47 ms。507 条标题和 506 条文件记录的迁移续跑约 1.34 秒，含注入中断和一次引擎重启。三组样本的负载和统计范围各异，生产规模迁移耗时仍未测量。 [引擎基线](SEARCH_PHASE1_REPORT.md) · [集成测试](../tests/test_manticore_queries.cpp)

## 阶段 5 验证后的修订（2026-11-24）

- 现有实例的性能日志显示，16:41 结束的一次报告间隔为 15.57 秒，平时间隔约 5 秒。期间有 11,737 次主线程 SQL 读取，节点的标题与文件查询各完成一次，两条完成日志相隔 12.63 秒，未记录桌面搜索提交。19:17 的另一次 13.50 秒间隔同样有节点的标题和文件查询以及 10,714 次主线程 SQL 读取。
- 桌面、REST 和节点全文查询改在后台执行，重复提交会取消前一个桌面查询的后续批次。远程命中分批更新表格。节点收到旧式请求时仍能应答，桌面只采纳带当前查询 ID 的新版应答，从而排除连续检索时无法归属的旧回包。
- 节点动态、复制和公告的种子入库也改在后台执行。应用日志 `rats-search.log` 记录至少 500 ms 的事件循环延迟，以及至少 250 ms 的主线程 SQL 操作和索引写锁等待。可将其与 `search.torrents_ms`、`search.files_ms` 计时对照排查。
- 搜索结果支持多选加入收藏及隐藏已收藏种子。收藏页支持文件夹和选中项的批量移动、移除，并可按选中项、当前文件夹或全部导出 JSON。已有收藏升级后归入「未分类」，添加时间保留。 [使用手册](MANUAL.md#organizing-and-exporting-favorites)
- Windows MinGW 的 34 项 CTest 全部通过。注入 3 秒查询阻塞时主事件循环持续处理定时器，旧查询回调未被采纳。双节点测试覆盖同词重搜、迟到新版和旧版回包，以及 64 条动态种子的后台入库。另验证旧收藏载入、批量操作、实时过滤与导出。解压验证包复测了新旧节点互通及 v1.1.0 数据目录升级，ZIP 的 SHA-256 校验通过。当前运行中的生产数据目录尚未用新版做长期复测。 [节点与阻塞测试](../tests/test_peer_search.cpp) · [收藏测试](../tests/test_favorites_store.cpp)

## 里程碑与验证命令

| 里程碑 | 阶段 | 可验收交付 |
| --- | --- | --- |
| 多语言基础搜索 | 1–3 | 本地及 REST 的多语言、精确短语、空格多词匹配，包含路径高亮、分页和旧库迁移。 |
| 高级搜索发布 | 4–5 | 可选模糊查找、节点协议兼容、文档和发布包验证。 |

在配置好 Qt 和编译器运行时的 Windows 环境中，优先运行聚焦测试，再跑全量构建和打包。现有构建目录为 `build-windows-x64`。验证包使用独立后缀。正式打包前先确认目标版本号和发布提交。

```powershell
ctest --test-dir build-windows-x64 -R '^(test_query|test_search_results|test_manticore_queries|test_peer_search)$' --output-on-failure
.\build-windows.cmd -Offline -PackageSuffix search-validation
```
