# 多语言与高级搜索执行计划

以 v1.1.0 为基线。先交付多语言匹配、引号短语和空格多词搜索，再交付模糊查找和跨节点验证。

## 查询约定

| 输入 | 预期行为 |
| --- | --- |
| `电影` | 匹配标题或路径中的连续子串，如 `经典电影合集`。排除 `电台摄影`。 |
| `电影 1080p` | 空格或全角空格分隔条件，所有条件都必须出现，顺序不限。 |
| `"星际 穿越"`、`“星际 穿越”` | 按分词后的顺序和相邻位置匹配短语。允许短语前后有其他内容，排除 `星际 经典 穿越`。 |
| `"导演剪辑版" 1080p` | 同时满足短语和普通词条件。 |
| `ubun*` | 保留现有显式通配符行为。引号内的星号不展开。 |
| `ubntu`、`星际穿悦`（开启模糊查找） | 可补充 `ubuntu`、`星际穿越`。普通命中在前，模糊命中在后。 |

引号短语使用索引的大小写、标点和空白规则。文件搜索的所有条件必须落在同一条文件路径上，命中路径原样显示并标注高亮。名称或路径的普通搜索保持现有类型、安全搜索、大小、文件数和排序规则。40 位十六进制 Info Hash 继续走精确查询。未闭合引号给出可纠正的提示。

## 阶段 1：验证随包 Manticore

1. 用随包 `searchd` 启动临时实例，为标题和文件路径分别验证 `charset_table = non_cont`、`ngram_len = 1`、`ngram_chars = cont`。
2. 准备中文、日文、韩文、泰文、中英混排和英文样本，验证连续位置、短语、英文通配符和路径高亮。记录索引大小及普通查询延迟基线。
3. 验收 `电影` 能匹配连续文字，并排除错序、隔字样本。现有英文搜索测试通过。用真实索引确认行为后再接入应用。

## 阶段 2：统一查询解析

1. 在共享搜索调用路径解析普通词、直引号和中文引号短语、显式通配符。按 Unicode 空白拆分普通词，由程序组合 AND 表达式并转义用户文本。
2. 标题和文件查询使用相同的解析结果。桌面与 REST 输出一致的语法提示。用共享长度规则放行两字连续文字查询，保留现有英文短词规则。
3. 验收正常短语、混合条件、全角空格、未闭合引号、英文前缀、通配符及 Info Hash 行为。

## 阶段 3：路径校验与已有索引迁移

1. 文件搜索根据索引召回候选，验证单条路径是否包含所有条件，只高亮实际命中的路径。应用所属种子的筛选并按哈希合并后再分页，验证页间无重复和漏项。
2. 接入现有迁移机制，重载标题与路径索引的分词设置，再批量重写旧记录。以成功写入的批次保存进度，续跑时复用原哈希、文件列表、分类和统计数据。
3. 验收升级前已有种子、新增种子和导入种子均可检索。覆盖跨文件凑词、文件高亮、筛选分页、中途退出续跑和升级前后数据一致性。

## 阶段 4：可选模糊查找

1. 桌面增加「模糊查找」开关，REST 增加 `fuzzy` 参数，默认关闭。
2. 先执行正常查询，再使用索引召回有限候选并校验编辑距离。首版只对至少四字符的普通词放宽，每次查询最多放宽一个词，允许一次插入、删除或替换。引号短语、显式通配符和 Info Hash 继续按原规则处理。
3. 普通结果优先，按哈希去重，各组沿用原排序与筛选。以样本验证候选上限、延迟和召回率，再根据结果确定候选策略和预算。当前 Windows 随包未提供 Buddy，首选由应用控制召回和校验。
4. 验收 `ubntu`、`星际穿悦`、短词、引号与模糊词组合、无候选及超出候选预算等场景。

## 阶段 5：节点互通与发布验收

1. 给支持新语法的 Rats 节点传递匹配选项与查询 ID，发送端仅接收当前查询的回复。旧节点继续处理兼容的普通请求。
2. 双节点验证两字查询、精确短语、文件命中、模糊查找选项和旧回复丢弃。验证升级前后节点互通。
3. 更新搜索帮助与 API 示例，记录普通和模糊查询延迟、索引大小、历史数据迁移耗时。运行现有查询单元测试和真实 Manticore 集成测试，并用打包后的程序复验。

## 交付顺序

- 阶段 1–3：多语言、引号和空格多词搜索，含已有索引迁移。
- 阶段 4–5：模糊查找、节点互通及发布验证。
