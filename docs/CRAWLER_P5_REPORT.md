# P5：异常恢复、确定性测试与长时验证

日期：2026-11-21。分支：`feat/crawler-p0-observability`，延续 P0–P4 工作区修改。没有创建提交、合并或发布；既有 P1 验证 ZIP 保留。

## P5-01：可控时钟与回调异常

新增 [CrawlerTiming](../src/common/crawler_timing.h)，生产使用单调性能时钟和有界随机抖动；测试注入可手动推进的时钟及确定抖动。时钟供给者用于数据库后台工作时必须线程安全。它没有改变用户配置或生产默认值。

[流水线测试](../tests/test_crawler_pipeline.cpp) 直接推进时钟，验证 99/100 毫秒的稀疏批次边界、250/500 毫秒的重试边界、60 秒重试总期限及等待在繁忙 worker 后方时过期的重试。实际 SQL 已开始后仍由底层超时处理，不承诺强行中断正在执行的查询。

[爬虫测试](../tests/test_crawler_metrics.cpp) 覆盖同步完成、重复完成、回调后抛异常、乱序完成、旧代次回复，以及虚拟时间下的网络退避和 120 秒总期限。重复回调现在在计算指标及投递 Qt 事件之前竞争同一个原子完成标志，避免重复成功/失败计数；获取接口在已经交付回调后抛异常，不再抢先将该任务结算为失败。

同时修正了以下调度与生命周期边界：

- 计时事件到来后再次检查单调时钟；尚未到期的稀疏任务重新安排，不因提前到来的计时事件过早提交。
- 数据库线程退出后移除尚未交付的流水线结果事件，立即销毁其捕获数据，再释放容量供下一轮使用。100 次连续停止/启动用弱引用验证捕获对象已经销毁，而非只靠 generation 忽略旧回复。
- [Manticore::stop](../src/data/manticore.cpp) 释放所有者线程的连接；数据库工作线程仍在自身线程先释放自己的连接。
- 停止时先注销网络公告；传输线程退出后再清理与注销竞争的晚到公告、唤醒事件及其发现名额，避免它们残留到最终退出或下一轮。专门的回归测试验证这一窗口。

既有异步测试仍使用事件循环等待真正的 worker 回答；虚拟时间用于调度和边界验证，不把逻辑时间冒充实际运行时长。

## P5-02：真实临时数据库故障回归

[test_crawler_batch_indexing.cpp](../tests/test_crawler_batch_indexing.cpp) 增加完整流水线自动恢复：

- 一个批次分成多个 SQL 子批次，第二个摘要写入失败；仅重试未确认项，最终 12 条均有完整文件列表，恰好 12 次新增通知和 12 条统计增量。
- 摘要已经提交但确认丢失，随后一次验证读取也失败；统计恢复后重放取回新增凭据，最终通知和统计不重复。

[test_manticore_queries.cpp](../tests/test_manticore_queries.cpp) 将真实 SQL 连接启停扩展到 100 次，每轮验证爬虫 SQL 不在主线程、工作线程连接停止后回落、写入/查重结果正确。保留并发单条/批量索引、大小写 hash、ID 碰撞、文件补齐、投票/tracker/信息合并、插入与删除、导入续传等现有覆盖。

另有实际断连恢复测试：保持流水线 worker 和已打开的连接存活，停止临时 searchd，确认读取错误进入退避而非返回“缺失”；在相同端口重新启动 searchd 后推进可控时钟，自动重连查询成功。该集成目标共 35 项通过，日志见 [p5-reconnect-tests.log](../build-windows-x64/p5-reconnect-tests.log)。

最初扩大启停次数时，测试数据编号与同库另一个 fixture 的编号重叠，导致“应发生新增写入”的断言失败；已改用独立编号范围后重新运行。该问题属于测试输入冲突，不以跳过断言处理。

全部测试使用新建临时目录和独立 searchd。P5 最终构建通过，全量 CTest **31/31 通过**，约 126.67 秒，日志见 [p5-full-tests.log](../build-windows-x64/p5-full-tests.log)。

## P5-03：启停与墙钟长测

工具：[crawler_soak_probe.cpp](../benchmarks/crawler/crawler_soak_probe.cpp)、扩展的 [crawler_live_probe.cpp](../benchmarks/crawler/crawler_live_probe.cpp)、[run-soak.ps1](../benchmarks/crawler/run-soak.ps1)、[run-network-soak.ps1](../benchmarks/crawler/run-network-soak.ps1)、[汇总脚本](../benchmarks/crawler/summarize-soak.cjs)、[归档脚本](../benchmarks/crawler/archive-soak.cjs)。

两个探针并行运行，先等第一个临时数据库就绪，再启动第二个，避免自动选端口时竞争同一端口。运行前保存探针二进制副本及 SHA-256，后续构建不会替换正在接受验证的程序。两者均使用精确墙钟截止计时器，不能用虚拟时间完成两小时验证。

可控探针每 250 毫秒产生两个候选，使用真实查重、预留、SQL、通知路径；元数据可同步完成、重复回调或模拟 timeout。每 30 秒注入约 2 秒数据库读取/写入不可用，重试恢复继续处理；这是临时真实数据库前的错误注入，不是强杀 searchd。100 次启停分布到整个窗口，每次额外保留一个实际元数据获取回调跨代次，再重复交付旧回调；同时变更并发及批次配置。逐轮检查工作线程连接回落到基线。

网络探针使用真实传输和 DHT、独立临时库，关闭其他入库来源，同样分布执行 100 次爬虫/流水线启停。网络传输维护不因暂停索引而停止。探针每秒流式记录资源，内存中只保留基线和最多 1,023 个近期样本，避免采样容器自行持续增长。

本次明确观察到环境差异：受限沙箱内探针的 DHT 节点持续为 0；同一个二进制经批准在沙箱外运行 10 秒获得 67 个节点。因此另起同版本、独立两小时的沙箱外网络长测，汇总采用该次网络结果。该证据只说明本次环境差异，不追溯断言 P0/P4 的所有历史低流量都由同一原因造成。mDNS 的 10049 警告在两种环境中都出现，不能单独据此判定 DHT 失败。

第一轮两小时尝试约 11 分钟时，发现上述晚到公告清理窗口并主动取消；修复后重新开始完整两小时，该次取消记录保留，不计为通过，也不拼接不同版本时长。

短时预检查：30 秒 / 3 次启停的双探针正常退出，可控场景数据库 200 条、已交付通知 197 条，统计精确，容量接纳 487 = 完成 458 + 取消 29，停止后两者连接均为 0。已确认的写入可能在通知交付前被一次停止打断，所以行数与通知数不必相等。另有 30 秒 / 100 次快速启停用于密集取消检查，不能把它称为两小时长测。

受控与沙箱外真实网络两次独立运行均已完成两小时、各 100 次启停。[最终汇总](../benchmarks/crawler/results/p5-soak-summary.json) 的 `longValidation` 和 `continuousSampling` 均为 true。[原始结果与压缩资源归档](../benchmarks/crawler/results/p5/archive.json) 保存 SHA-256 并通过逐个解压还原校验；未收录可能包含种子内容的诊断日志。

受控结果：实际墙钟 7,200,392 毫秒，100 次启停，真实数据库 53,875 条，统计一致；53,867 次新增通知。容量接纳 124,857 = 完成 124,587 + 取消 270，注入故障期间数据库退避 9,922 次、网络退避 9,805 次。停止后连接、数据库待处理、在途元数据和发现名额均为 0；每次停止工作连接回落到基线 1，最终数据库停止后降为 0。

内部指标记录到待处理峰值 21、在途元数据峰值 9、估算预算峰值 37,754,608 字节，均在上限内。1 Hz 的采样峰值会低于瞬时内部指标峰值；预算也不等同于进程内存。采样 7,202 条，最大间隔 1,072 毫秒。

受控进程首个稳态窗口（第 15–30 分钟）与最后 15 分钟相比：平均 RSS 22.22 → 21.14 MiB，平均 private memory 8.92 → 9.81 MiB，平均线程数均为 5；private memory 回归斜率约 +0.52 MiB/小时。队列和连接不随启停累积，但这段小幅内存增长不能仅凭两小时归因为泄漏或证明完全无泄漏；报告保留实际趋势，未宣称内存绝对不增长。

真实网络结果：实际墙钟 7,200,372 毫秒，100 次启停，结束前 DHT 节点 244。收到 4 次公告，4 次元数据尝试，1 次成功并新增入库 1 条，3 次超时失败；本窗口没有发起网络重试。停止后连接、数据库待处理、元数据在途和发现名额均归零。样本只能证明本次真实发现到入库路径有成功完成，不足以评价公网成功率或提高并发后的吞吐收益。

## P5-04：默认值与运行语义

默认并发仍为 10；发现总名额 5,000、数据库/结果/重试共享任务 1,000、估算字节预算 64 MiB、单个结果预留 4 MiB、批次最大 100 / 最老等待 100 毫秒、高低水位 80%/50% 均保留。64 档没有性能测量证据，不作为推荐值。没有引入多个数据库写线程，也没有改写 librats 等待线程。

P0 的真实网络正式窗口仅见极少公告，没有有效新增吞吐基线。P2 的固定输入 SQL 结果显示批量减少往返，但它测的是数据库服务；P4 的完整可控路径包含通知节流，两者不能用不同口径直接计算“整个爬虫提速倍数”。P5 的资源/故障长测也不是网络吞吐对照。历次原始记录和限制分别见 [P0](./CRAWLER_P0_REPORT.md)、[P2](./CRAWLER_P2_REPORT.md)、[P4](./CRAWLER_P4_REPORT.md) 报告。

[用户手册](./MANUAL.md) 已明确入口丢弃、重试耗尽、内存队列不持久化和停止时可能已提交但未通知的语义。重启后数据库保留已提交内容并重新统计；旧回调不会污染新代次。结果预留必须持续到网络回调结束或传输层完成等待。

[P5 验证摘要](../benchmarks/crawler/results/p5-validation.json) 保存全量测试、真实 daemon 重启回归、源码/二进制 SHA-256、长测归档索引与被排除的取消尝试。[执行计划](./CRAWLER_EXECUTION_PLAN.md) 的 P5-01～04 已完成登记。

## 复现

```powershell
# 将本地 Qt/MinGW bin 加入 PATH 后构建
& .tools/Qt/Tools/CMake_64/bin/cmake.exe --build build-windows-x64 -j 4
& .tools/Qt/Tools/CMake_64/bin/ctest.exe --test-dir build-windows-x64 --output-on-failure -j 4
& ./benchmarks/crawler/run-soak.ps1 -Seconds 7200 -Cycles 100 -OutputDirectory build-windows-x64/p5-new-controlled
# 网络环境受限时，在获准使用公网的环境运行同一份快照：
& ./benchmarks/crawler/run-network-soak.ps1 -Seconds 7200 -Cycles 100 -OutputDirectory build-windows-x64/p5-new-network
node benchmarks/crawler/summarize-soak.cjs build-windows-x64/p5-new-controlled build-windows-x64/p5-new-summary.json build-windows-x64/p5-new-network
node benchmarks/crawler/archive-soak.cjs build-windows-x64/p5-new-controlled build-windows-x64/p5-new-network build-windows-x64/p5-new-archive
```

复现应选择新的输出目录，避免覆盖原始证据。运行中若需要取消，可在该目录创建 `STOP` 文件，两个探针在下次采样时正常收尾；取消、时长不足或启停不足不会计为长测通过。资源只覆盖探针进程，排除 searchd 和系统总量；估算字节预算不是 RSS 硬上限，线上带宽未测。
